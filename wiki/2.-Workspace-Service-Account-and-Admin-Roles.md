# 2. Workspace Service Account and Admin Roles

Historically, GCDS required a human **Super Administrator** to click **"Authorize Now"** in GCDS Configuration Manager, saving a long-lived 3-legged OAuth (3LO) refresh token inside `sync-config.xml`. That token is encrypted only with a plaintext symmetric key stored in Java Preferences (`HKCU\Software\JavaSoft\Prefs` in the Windows Registry or `~/.java/.userPrefs` on Linux)—it is **not** hardware- or machine-bound. Because unattended GCDS can read that key directly, an attacker with access to the sync user account, registry hive, or VM backup can trivially extract the key and decrypt a Super Admin refresh token. Furthermore, if that human admin left the company or had their sessions reset, directory sync broke.

With `gcds-in-the-cloud`, we eliminate **both** human 3-legged OAuth **and** Domain-Wide Delegation (DwD) by assigning a **least-privilege Workspace Custom Admin Role directly to your Cloud Run Service Account**.

---

## How Keyless Service Account JWT Auth Works

1. Your Cloud Run Job runs as a dedicated GCP Service Account (`gcds-sync@<project>.iam.gserviceaccount.com`) with **zero downloaded JSON keys**.
2. In Google Workspace Admin Console, that Service Account email is assigned a **Custom Admin Role** containing *only* the directory privileges GCDS needs.
3. Inside the container:
   * When GCDS calls `POST https://oauth2.googleapis.com/token` to refresh its dummy OAuth token, `go-oauth-proxy` intercepts the call locally and returns a synthetic `200 OK` placeholder token. **`oauth2.googleapis.com` is never contacted.**
   * When GCDS calls `https://admin.googleapis.com/...`, `go-oauth-proxy` strips the placeholder header, calls GCP's IAM Credentials API (`projects/-/serviceAccounts/gcds-sync@...:signJwt`) via the Cloud Run Metadata Server, caches the Google-signed JWT (`iss == sub == gcds-sync@...`, `aud == "https://admin.googleapis.com/"`), and injects `Authorization: Bearer <signed-jwt>`.

---

## Step 1: Create the Keyless GCP Service Account

*(If you run `deploy/cloud-run/deploy.sh`, this Service Account and self-signing IAM binding are created automatically.)*

```bash
export PROJECT_ID="your-gcp-project"
export SA_EMAIL="gcds-sync@${PROJECT_ID}.iam.gserviceaccount.com"

gcloud services enable iam.googleapis.com iamcredentials.googleapis.com admin.googleapis.com \
  --project="$PROJECT_ID"

gcloud iam service-accounts create gcds-sync \
  --display-name="GCDS Cloud Run Sync Service Account" \
  --project="$PROJECT_ID"

# Allow the Service Account to sign its own JWTs via IAM :signJwt (Google-managed keys)
gcloud iam service-accounts add-iam-policy-binding "$SA_EMAIL" \
  --member="serviceAccount:${SA_EMAIL}" \
  --role="roles/iam.serviceAccountTokenCreator" \
  --project="$PROJECT_ID"
```

> **Best Practice**: Enforce the `constraints/iam.disableServiceAccountKeyCreation` Organization Policy on this project so nobody can accidentally create a downloadable JSON key for `gcds-sync`.

---

## Step 2: Create a Least-Privilege Custom Admin Role in Google Workspace

1. Sign in to **[admin.google.com](https://admin.google.com)** -> **Account** -> **Admin roles**.
2. Click **Create new role**, name it **`GCDS Directory Sync Automation`**, and click **Continue**.
3. Scroll down to **Admin API privileges** *(skip "Admin console privileges"—a Service Account never logs into the web UI)* and select **only** the privileges matching the features enabled in your `sync-config.xml`:

| GCDS Sync Feature Enabled | Required Workspace **Admin API Privileges** |
| :--- | :--- |
| **Org Units** | **Organizational Units**: *Read, Create, Update, Delete* |
| **User Accounts & Aliases** | **Users**: *Read, Create, Update*, plus *Force Password Change*, *Suspend Users* (and *Delete* ONLY if GCDS is configured to delete rather than suspend) |
| **Custom User Schemas** | **Schema Management** (under Custom Fields / Users): *Read* (and *Manage* if creating schemas) |
| **Groups & Group Memberships** | **Groups**: *Read, Create, Update, Delete* |
| **License Sync** *(if enabled)* | **License Management** |

4. Click **Continue** -> **Create Role**.

---

## Step 3: Assign the Role Directly to the GCP Service Account

1. Inside your newly created **`GCDS Directory Sync Automation`** role in `admin.google.com`, click **Assign admin** -> **Assign service accounts**.
2. Paste your Service Account email:
   ```text
   gcds-sync@your-gcp-project.iam.gserviceaccount.com
   ```
3. Click **Add** -> **Assign role**.

*(Propagation typically completes within 1–5 minutes.)*
